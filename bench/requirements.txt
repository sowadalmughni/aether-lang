# Aether benchmark Python dependencies.
#
# langchain and dspy stacks: exact pins. bench/baselines/langchain_baseline.py
# imports real langchain symbols (LCEL chains, RunnableParallel, InMemoryCache);
# bench/baselines/dspy_baseline.py imports real DSPy symbols (BaseLM, Signature,
# Module, Predict, ChainOfThought, ChatAdapter). The numbers in
# bench/results/langchain_v1.json and bench/results/dspy_v1.json are tied to
# these exact versions, so loosening the pins would break artifact-evaluation
# reproducibility.
#
# NOTE on DSPy: `dspy-ai` is now a metadata-only alias for the `dspy`
# package (https://pypi.org/project/dspy-ai/), so pinning `dspy-ai==2.6.27`
# alone would let the underlying `dspy` package float (it currently resolves
# to dspy 3.2.1, released 2026-05-05). We pin BOTH `dspy-ai==2.6.27` and
# `dspy==2.6.27` to keep `import dspy` -> 2.6.27 deterministic.

langchain==0.3.28
langchain-core==0.3.84
langchain-openai==0.2.14
langchain-anthropic==0.2.4
dspy-ai==2.6.27
dspy==2.6.27
datasets>=2.20,<4.0
numpy>=1.26,<3.0
scipy>=1.13,<2.0
httpx>=0.27,<1.0

# bench/figures/generate_figures.py — produces the publication figures
# in whitepaper/latex/figures/ from the JSONs in bench/results/. Pinned

matplotlib>=3.8,<4.0

# bench/security — direct prompt-injection benchmark.
#
# Uses attack content adapted from InjecAgent
# (https://github.com/uiuc-kang-lab/InjecAgent), used under that
# project's license. We do NOT depend on the InjecAgent Python
# package: their harness is for tool-using agents and does not align
# with Aether's prompt-level taint model. Instead we vendor a JSON
# subset of their test cases under bench/security/data/ and reuse
# only the attacker-instruction strings + expected-achievement
# descriptors in a direct-prompt-injection harness.
#
# Pinned to the lowest version that simultaneously satisfies:
#   - langchain-openai 0.2.14 (requires openai>=1.58.1,<2.0.0)
#   - litellm 1.69.2        (requires openai>=1.68.2,<1.76.0)
# Older pins (1.55.0, 1.58.1) became unresolvable as the transitive
# litellm dependency (pulled in by dspy>=2.6.27) tightened its lower
# bound on openai. The committed real-API JSONs in bench/results/ were
# measured at openai 1.55.0; reproduce.sh runs mock-mode only and does
# not call api.openai.com, so a third party rerunning reproduce.sh with
# this pin still hits the mock provider and produces matching JSONs.
# Real-API reruns under this pin may differ in latency/cost; that is
# expected and out of reproduce.sh's scope (see REPRODUCIBILITY.md §6).
openai==1.68.2

# litellm is a transitive dependency of dspy==2.6.27 (which only
# specifies `litellm>=1.60.3`). It is pinned explicitly here because
# litellm's lower bound on openai has shifted repeatedly upward over
# 2025-2026 (1.61 -> 1.66.1 -> 1.68.2 -> 2.8.0 at 1.80+); without an
# explicit pin, pip's resolver picks whatever litellm is "latest at
# resolve time" and the openai constraint is unstable across rebuilds.
# 1.69.2 sits in the [openai 1.68.2, 1.76.0) band that langchain-openai
# 0.2.14 also accepts. Mock-mode only, so litellm version does not
# affect committed bench JSONs.
litellm==1.69.2
